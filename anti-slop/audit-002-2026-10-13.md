# Post-implementation audit 002

13 October 2026 WIB. Follow-up authorized by the user after implementation. Scope: all nine dashboard workspaces, kit glyph integration, application controls, error states and explicit documentation of unsupported functions. Source direction: `docs/.agents/dashboard_revamp/titipin-mlops-design-kit-v1.1.0/titipin-mlops-design-kit/` HTML, SVG and semantic tokens. ENERGY 1 / RHYTHM 2 / MOTION 1.

## Findings and disposition

1. **HIGH, UI resolved / backend remains open:** previous audit 001 finding 2. Removed successful audit fallback, invented simulator predictions/latency, fixed HPA benchmark values, fabricated retraining completion and fake FinOps live/efficiency claims. API errors produce explicit failure/unknown states. Backend still seeds history/counters and demonstration metadata; this cannot be cured by relabeling raw JSON. Source warnings are visible; unsupported mutations are disabled. Exact backend follow-ups: `docs/dashboard-revamp/FUNCTIONALITY.md`.
2. **HIGH, resolved:** five old workload state names were not recognized by the installed daemon. Five enabled buttons now submit supported states and validate API acknowledgement. Live daemon state definitions were inspected over SSH and matched the repository. Drift stays disabled because its supported state also invokes demonstrative orchestration. The undocumented chaos state was replaced by supported cooldown.
3. **HIGH, resolved in UI / backend capability absent:** lifecycle start/stop buttons targeted routes missing from both source and production OpenAPI. Removed the misleading controls and documented the absence. Coordinator metadata remains read-only. Manual retraining is disabled because the existing endpoint changes model metadata and reports promotion before confirmed job completion.
4. **MEDIUM, resolved:** workload requests ignored HTTP responses and could throw uncaught network errors. All enabled buttons now handle HTTP failure/timeout/invalid JSON and verify matching acknowledgement. Browser testing found old accepted feedback surviving a failed subsequent request; a placeholder populated after action processing fixes it, with a regression test. Request acceptance remains distinct from observed daemon execution.
5. **MEDIUM, resolved:** simulator presets did not consistently update keyed sliders after manual edits; failed inference could preserve stale output or fabricate success. Keyed presets now update all inputs, the previous result is cleared on failure, and changed inputs identify the last submission. Local policy preview and API recommendation are separate values.
6. **MEDIUM, resolved:** injector polled every two seconds even when Auto-refresh was off. It now uses the shared read interval. Auto-refresh and interval controls are disabled with an explanation in manual/calculator/static workspaces. Polling does not submit actions.
7. **MEDIUM, resolved:** injector cards forced dark colors and used emoji/fixed success narratives. Operational sections now use owned native panels, semantic theme colors, kit glyphs and measured/source-reported labels. Streamlit strips inline SVG; local base64 SVG images preserve supplied geometry, receive the current semantic foreground color, and use empty alt/aria-hidden beside text headings. No icon library, external font, gradient, glow or motion was added.
8. **MEDIUM, resolved:** Streamlit applied 0.6 opacity to native captions after the semantic text color, reducing actual text contrast. Owned CSS now removes that opacity; browser checks verify opacity 1 across all operational views and both themes. Existing palette ratios now also describe unattenuated caption foregrounds.
9. **LOW, retained:** native theme changes require Refresh now before owned tokens/icons/charts update. This remains explicit in the sidebar and documentation.

Existing Overview suite additionally covers five widths, export contents, keyboard refresh/skip link, and 200% text.
- Accessibility: text accompanies decorative glyphs; native controls retain names, disabled semantics and keyboard behavior. Injector keyboard activation is checked. Semantic palette contrast evidence from the initial revamp remains applicable; this is not WCAG certification or a pixel-level audit of every native widget.
- Architecture/security: Streamlit/FastAPI/scaler/daemon boundaries and configured URLs preserved. No secret or internal API URL enters HTML. No production mutation was used for testing. No new production dependency.
- Validation: see `docs/dashboard-revamp/FUNCTIONALITY.md`, `validation/controls.json`, and the cleanup release evidence. No end-to-end claim that real traffic/retraining succeeded is made from mocks or read-only inspection.

Audit 001 remains a historical snapshot. Its UI fallback/claim findings are addressed by this follow-up; backend provenance and verified lifecycle completion are still open, and the theme-refresh limitation remains.
